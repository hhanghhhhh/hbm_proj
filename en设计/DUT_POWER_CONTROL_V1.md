# 多板卡电源故障下电方案 V1

> 更新日期：2026-09-08。本文为初版实施方案；最新映射采用“表 A 存本地行号加一、表 B 升序紧凑存储、本地直接索引、远端二分查找”。
>
> 原则：上位机预先处理接线关系、共享关系和映射生成；FPGA 只负责查表、关断、锁定和故障通知。复杂容错及扩展能力放在后续升级章节。
>
> 本文规定拟实现行为，不表示现有 RTL 已完成这些功能。本文与旧文档不同之处，以本文描述的 V1 方案作为后续实现依据。

## 1. 范围与已确认条件

- 系统约 5000 个 DUT，每个 DUT 约 5 路电源，实际路数允许不同。
- 共 20 块板卡，每块板按 128 路电源 EN 管理；同一 DUT 的电源可能来自不同板卡。
- 一路电源可以供给多个 DUT，各 DUT 分支没有可独立控制的断电开关。
- 允许共用电源关联的 DUT 一起下电；被连带影响的 DUT 也应完整下电，避免只剩部分电源工作。
- 正常上电和正常下电仍为整机动作，使用各板本地 sequence + delay，通过 START_SYNC 同步。
- 故障关断不执行正常 OFF_SEQUENCE，直接关闭对应保护组。
- V1 不支持运行中修改接线配置、单组故障在线恢复或单组重新上电。

## 2. 关键改动：按保护组关断

### 2.1 保护组定义

把实际 DUT 与电源通道的供电关系连接起来，凡是通过共享电源直接或间接关联的 DUT 和电源，归为同一个保护组 GROUP。

例如：

```text
P1 -> DUT A、DUT B
P2 -> DUT B、DUT C
P3 -> DUT C
P4 -> DUT A

结果：A、B、C 和 P1、P2、P3、P4 属于同一个保护组。
```

A 故障时，关闭 P1 会使 B 缺少供电；继续关闭 B 的 P2 又会影响 C。因此应一次通知整个保护组关断，而不是让各板在运行时逐级推导关联关系。

上位机通过连通分量计算或并查集合并完成分组。FPGA 不保存完整 DUT 拓扑，不执行关联搜索。

V1 的隔离目标为：**关闭故障保护组的所有电源，不主动关闭其他保护组。**

### 2.2 上位机必须提前展示的结果

配置生成后，上位机展示每个保护组的 DUT 数量、电源数量和涉及板卡，便于确认实际关断范围。

如果公共电源把许多 DUT 连成一个大组，则这些 DUT 必须一起下电。这是接线决定的结果，不能通过软件把一个实际连通组拆成多个可独立关断的组。

### 2.3 上位机如何分组，保证一个 EN 引脚只属于一个组

#### 2.3.1 先给每个物理控制通道一个唯一身份

上位机用 `(BOARD_ID, CHANNEL_ID)` 作为电源通道的唯一键，不用 DUT_ID、电源名称或电压值作为通道身份。

例如 Board0.CH1 的键是 `(0, 1)`。即使它同时出现在 DUT A、DUT B 的接线记录里，也只代表一个物理通道，不能为两个 DUT 各建一份通道对象。

Board0.CH1 和 Board1.CH1 的键分别是 `(0, 1)`、`(1, 1)`，是两个不同引脚，不会因为通道号相同而自动归为一组。若接线文件使用了别名，必须先统一为实际的板卡和 EN 通道号。

沿用第 6.4 节的接线：

| 通道简称 | 唯一键 | 哪些 DUT 使用它 |
|---|---|---|
| P1 | (0, 1) | A、B |
| P2 | (1, 3) | B、C |
| P3 | (2, 6) | C |
| P4 | (0, 4) | A |
| P5 | (0, 7) | D |
| P6 | (1, 9) | D |
| P7 | (2, 2) | E |

上位机把接线整理成“每个 DUT 使用哪些通道”，同一 DUT 内重复的通道键去重：

```text
DUT A → {P1, P4}
DUT B → {P1, P2}
DUT C → {P2, P3}
DUT D → {P5, P6}
DUT E → {P7}
```

#### 2.3.2 初始每个通道一组，再按 DUT 合并整组

合并规则只有一条：**同一个 DUT 使用的所有电源通道，必须处于同一个保护组。**

上位机开始时给每个通道建立独立集合，然后逐个处理 DUT。合并的是通道所在的整个集合，不能只修改当前通道的分组标签。

| 步骤 | 当前处理 | 合并后的全部集合 |
|---|---|---|
| 初始 | 每个物理通道只出现一次 | {P1}、{P2}、{P3}、{P4}、{P5}、{P6}、{P7} |
| 1 | A 使用 P1、P4，合并两者所在集合 | {P1,P4}、{P2}、{P3}、{P5}、{P6}、{P7} |
| 2 | B 使用 P1、P2；P1 已属于 {P1,P4} | {P1,P2,P4}、{P3}、{P5}、{P6}、{P7} |
| 3 | C 使用 P2、P3；P2 已属于 {P1,P2,P4} | {P1,P2,P3,P4}、{P5}、{P6}、{P7} |
| 4 | D 使用 P5、P6，合并两者所在集合 | {P1,P2,P3,P4}、{P5,P6}、{P7} |
| 5 | E 仅使用 P7，无需合并 | {P1,P2,P3,P4}、{P5,P6}、{P7} |

共享关系会在这个过程中自动传递：处理 B 时，P1 指向已有集合，因此 P4 也随集合一起合并；处理 C 时，又把 P3 合并进去。无须 FPGA 再检查 A、B、C 之间的关系。

所有 DUT 处理完成后，再为最终集合分配 GROUP_ID。本例沿用后文编号：

```text
{P5,P6}       → GROUP_ID = 1
{P1,P2,P3,P4} → GROUP_ID = 2
{P7}          → GROUP_ID = 3
```

全局 GROUP_ID 从 1 到 G 连续分配，0 保留为无效值。本例使用上述编号顺序；实际上位机应固定集合排序规则，使同一份接线输入得到可重复的编号。各板只保留本板涉及的组，因此本板表 B 的组号可能不连续，但必须严格升序。不要在合并尚未完成时下发临时编号。

#### 2.3.3 为什么一个引脚不可能同时属于两个组

初始时，每个唯一通道只存在于一个集合。后续操作只会把两个集合合成一个集合，并撤掉原来的两个独立集合，不会复制通道，也不会拆分集合。

因此最终集合之间没有公共通道，每个已使用通道恰好属于一个集合，分配 GROUP_ID 后也就恰好属于一个组。

例如 P1 被 A、B 同时使用时，不能分别生成：

```text
错误：A 的组 = {P1,P4}，B 的组 = {P1,P2}
      P1 出现在两个组，关闭 A 时会影响尚未完整下电的 B。

正确：把有公共通道 P1 的两个集合合并为 {P1,P2,P4}。
      再处理 C 后得到 {P1,P2,P3,P4}。
```

上位机可用“并查集”实现：每个通道有一个父节点，`find(p)` 找到所属集合的根，`union(p,q)` 合并两个根。它只在上位机运行，板卡无需实现。

```text
used_channels = 所有接线中出现的 (BOARD_ID, CHANNEL_ID)，去重

对每个 p in used_channels：
    parent[p] = p                     // 初始一个通道一个集合

find(p)：
    若 parent[p] != p：
        parent[p] = find(parent[p])    // 路径压缩
    返回 parent[p]

union(p, q)：
    rp = find(p)
    rq = find(q)
    若 rp != rq：
        较大通道键的根.parent = 较小通道键的根

对每个 DUT：
    pins = 该 DUT 使用的通道键，去重
    检查 pins 非空
    对 pins 中除第一个以外的每个 p：
        union(pins[0], p)

全部合并完成后：
    按 find(p) 收集所有通道，形成最终集合
    为每个最终集合分配一个全局 GROUP_ID
    对集合中的每个 p：channel_to_group[p] = 该 GROUP_ID
```

改变 DUT 的处理顺序，不会改变最终哪些通道必须在一起。新接线增加或移除后，V1 直接从完整接线重新计算；尤其移除连接可能导致原组拆分，不能只靠继续做 union 更新旧结果。

#### 2.3.4 从唯一分组结果生成表 A、表 B

两张表必须由同一份 `channel_to_group` 生成，不让操作员分别手填：

```text
所有板表 A 初始化为 0，表 B 的全部预留行初始化为 0

先在上位机建立临时字典：
遍历 channel_to_group 中的每一项：
    (board, channel) → group_id
    group_masks[board][group_id] |= (1 << channel)  // 使用128位掩码

对每块板：
    按 group_id 升序把 group_masks 写入表 B 的有效行
    建立 group_id → 本地 row 的临时对应表
    对本板每个已使用 channel：
        row = 该通道所属 group_id 在表 B 中的行号
        表A[board][channel] = row + 1

设置 GROUP_COUNT，完整下发表 A 和表 B 的预留区域，未用项为 0
```

必须先排序表 B，再生成表 A；上述字典仅在上位机使用，FPGA 不保存全局组号直接索引的大数组。

例如 Board0 的三条唯一分组结果为：

```text
(0,1)、(0,4) → GROUP_ID=2：组2掩码置 bit1、bit4
(0,7)       → GROUP_ID=1：组1掩码置 bit7

排序后：表B row=0 存组1；row=1 存组2
生成表A：表A[1]=2；表A[4]=2；表A[7]=1   // 均为 row+1，不是组号

最终：
组1的本板掩码 = 0x0080
组2的本板掩码 = 0x0012
两者按位与         = 0x0000，说明没有重复使用本板引脚
```

下发前，上位机至少做以下检查，失败则不允许提交配置：

1. 每个工作 DUT 都有完整的供电连接；每个通道键在实际硬件范围内。
2. 每个已使用通道恰好有一个 GROUP_ID；同一 DUT 的所有通道最终 GROUP_ID 相同。
3. 同一板卡各组 EN_MASK 两两按位与为 0，所有掩码按位或等于该板已使用通道集合。
4. 表 B 有效行的 GROUP_ID 严格升序且不重复；表 A 有效值在 1..GROUP_COUNT，减一所得行的掩码必须包含该通道；表 B 每个置 1 的 bit 对应的表 A 项必须等于该行 row+1。
5. 正常 sequence 会开启的通道都具有有效映射，未使用通道不能被开启。

这里的掩码重叠检查仅在同一板内进行。Board0 的 bit1 与 Board1 的 bit1 是不同引脚，即使属于不同组也不冲突。

若后续新增 DUT F，使用 P4 和 P5，上位机会把原来的 `{P1,P2,P3,P4}` 与 `{P5,P6}` 合成一个组，重新生成各板表 A/B；不能保留两个旧组并把 P4 或 P5 重复放入新组。V1 在整机停止后重新下发整套配置。

### 2.4 供电接线设计准则：限制故障影响范围

**先规定每组最多允许多少个 DUT 一起下电，再安排供电接线。** 建议遵守以下准则：

1. **各路电源使用同一分组边界。** 例如 DUT0～9 为一组，其五路电源都只供组内 DUT；允许某一路在组内拆成多个电源通道，但不允许跨组共享。
2. **避免错位共享。** 若一路供 DUT0～9，另一路供 DUT5～14，两批 DUT 就会关联成更大的保护组。需要随 DUT 故障关闭的辅助电源也必须遵守组边界。
3. **完整保护组优先放在同板。** 必须跨板时，尽量限定在固定的少量板卡内。分别限制“每组 DUT 数量”“每组涉及板卡数”“单板失效涉及的 DUT 总数”；单组故障范围小，不代表整板失效范围也小。
4. **核对电气保护边界。** 检查分支限流、短路切断、公共输入压降及反向供电路径，避免一组短路拖垮其他组；实际保护能力结合器件和硬件验证确定。
5. **上位机检查期望分组与实际接线。** 为 DUT 预设 DESIGN_GROUP；发现一个通道连接多个期望组时，指出具体通道和 DUT。再用第 2.3 节算法计算实际保护组，检查是否超出允许范围。期望标签不能覆盖真实关联关系。

```text
推荐：G0 的五路电源 → 仅 DUT0～9；G1 的五路电源 → 仅 DUT10～19
检查：Board3.CH27 同时供 DUT8、DUT12 → 跨越 G0/G1，需调整接线
```

通道预算可先按 `ceil(5000 / 每组DUT数) × 5` 估算，前提是每组五路电源各自能带动全组负载、组间不共享输出：

| 每组最多 DUT 数 | 所需通道数 | 20×128 路的剩余通道 |
|---|---|---|
| 10 | 2500 | 60 |
| 12 | 2085 | 475 |

10～12 个一组仅作为预算起点，还需核算电流、启动负载、压降、温升及备用通道。若实际每板仅有 112 路，共 2240 路，上述 10 个一组的方案通道不足；组内某路需要拆分供电时，也要增加预算。

## 3. 上位机与 FPGA 的分工

| 工作 | 上位机 | FPGA |
|---|---|---|
| 保存 DUT 编号及电源角色 | 保存完整数据 | 不需要 |
| 维护跨板接线关系 | 负责 | 不需要 |
| 计算共享电源关联闭包 | 负责，预先生成保护组 | 不需要 |
| 生成本板 ON/OFF sequence | 负责 | 保存并执行 |
| 生成本板故障映射 | 负责 | 保存并查表 |
| 检查配置一致性 | 全系统检查 | 必要的长度、范围和有效性检查 |
| 故障关断与锁定 | 不参与实时闭环 | 负责 |
| 跨板 KILL/ACK/重试 | 不参与实时闭环 | 负责 |
| 故障显示与清除流程 | 组织和显示 | 执行清除条件检查 |

上位机原始接线数据建议每条连接包含：

```text
DUT_ID      : uint16
RAIL_ID     : uint8，表示 DUT 的电源角色
BOARD_ID    : uint8，0..19
CHANNEL_ID  : uint8，0..127
```

一个 DUT 有多少路电源，就保存多少条连接，不固定为 5 条。DUT_ID 仅用于上位机管理；故障总线使用 GROUP_ID。

## 4. V1 板卡映射格式

### 4.1 编号约定

- BOARD_ID：0..19。
- CHANNEL_ID：0..127，EN_MASK 的 bit n 对应本板通道 n。
- GROUP_ID：16 bit，全系统按 1..GLOBAL_GROUP_COUNT 连续分配，0 和 0xFFFF 保留为无效值。
- 本地保护组表行号：0..GROUP_COUNT-1，最多 128 行。行号仅供本板 RAM 和 pending 位图使用，不在板间传输。
- 表 A 行号编码：0 表示未使用；1..128 表示本地 row+1，使用前还须检查不超过本板 GROUP_COUNT。
- 上位机为一套配置生成固定 GROUP_ID，在本次运行期间不得重新编号。

### 4.2 表 A：本板通道到表 B 的直接索引

```text
CHANNEL_ROW_CODE[0..127] : 每项 16 bit

有效通道：保存所属组在本板表 B 中的 row + 1
未使用通道：保存 0x0000
```

容量：128 × 2 = 256 Byte。

本地 CH37 报故障时，读取 CHANNEL_ROW_CODE[37]，确认在 1..GROUP_COUNT 后减一得到 row，直接读取表 B 对应行的 GROUP_ID 和 EN_MASK。无需搜索组号。值为 128 时对应 row=127；不能先截断为 7 bit 再减一。

### 4.3 表 B：保护组在本板的 EN 掩码

每行固定 9 个 16 bit word，共 18 Byte：

| 行内 word | 内容 |
|---|---|
| 0 | GROUP_ID |
| 1 | EN_MASK[15:0] |
| 2 | EN_MASK[31:16] |
| 3 | EN_MASK[47:32] |
| 4 | EN_MASK[63:48] |
| 5 | EN_MASK[79:64] |
| 6 | EN_MASK[95:80] |
| 7 | EN_MASK[111:96] |
| 8 | EN_MASK[127:112] |

只把本板实际涉及且 EN_MASK 非零的组放入有效行，并按 GROUP_ID 严格升序排列。GROUP_COUNT 指示有效行数；其后到第 127 行全部填 0，不参与查找。

因为一个本地通道只能属于一个保护组，本板最多涉及 128 个组。表 B 最大容量为 128 × 18 = 2304 Byte。

两表合计最大为 **2560 Byte，即 2.5 KiB/板**，不包含配置头、运行状态和 RAM 分配取整。

V1 不保存 DUT 列表、保护组成员板卡掩码或全系统保护组大表。

### 4.4 建议 RAM 地址布局

使用独立的 16 bit 映射 RAM，地址单位为 word：

```text
RAM[0..127]                = CHANNEL_ROW_CODE[0..127]
RAM[128 + row*9 + 0]       = GROUP_ID
RAM[128 + row*9 + 1..8]    = 本板 EN_MASK
```

最多占用 1280 words，地址口至少 11 bit。若使用 2048×16 RAM，实际分配为 4 KiB。

该映射 RAM 与现有 sequence RAM 分开；不要把 1280 words 映射塞入现有 1024×16 sequence RAM。

每个 16 bit word 在线路上高字节先发；掩码 word 按低 16 bit 到高 16 bit 排列，与现有 sequence 中的 EN word 顺序一致。

### 4.5 查找方式：本地直接索引，远端二分查找

本地故障：读表 A 得 row+1，检查范围后直接读取表 B 的该行，返回 GROUP_ID、row、EN_MASK。发送 pending[row] 时也直接读该行，不搜索组号。

远端故障：收到合法 GROUP_ID 后，对表 B 的有效行做二分查找。采用左闭右开区间，避免无符号减一造成边界下溢：

```text
lo = 0；hi = GROUP_COUNT                 // 搜索区间 [lo, hi)
当 lo < hi：
    mid = (lo + hi) >> 1
    读取 RAM[128 + mid*9]，等待返回 candidate_id
    candidate_id < 目标：lo = mid + 1
    candidate_id > 目标：hi = mid
    candidate_id = 目标：读取该行 8 个掩码 word，返回找到
区间为空：返回本板无该组
```

lo/hi 至少为 8 bit，允许 hi=128；求和先扩位再右移。GROUP_COUNT=0 时直接返回未找到，不发起 RAM 读。最多 128 个有效组时，最多比较 8 次 ID；找到后仍需固定读取 8 个掩码 word。比较次数不等于时钟周期数，同步 RAM 的请求/等待/结果由状态机处理。

例如本板组号为 `[3,12,27,41,58,76,103,125]`，找 103 时，依次比较 row=4 的 58、row=6 的 103，两次即找到；组号空洞表示这些组不在本板，不需要为其预留行。

两张表由上位机同一次生成：先排序表 B，再生成表 A。各组掩码不得重叠，索引须双向一致；ACK 必须在本次掩码已经锁存后发出。容量仍为 2.5 KiB，不改为全局 GROUP_ID 直接寻址的大数组。

两表的具体内容、RAM 地址、报文和逐板动作见第 6.4 节的完整例子。

## 5. 配置与启动流程

### 5.1 最少配置元数据

```text
FORMAT_VERSION : uint16，本次映射格式修订为 2
CONFIG_ID      : uint32，上位机分配，全系统一致
BOARD_ID       : uint8
GROUP_COUNT    : uint8，本板有效行数，0..128
GLOBAL_GROUP_COUNT : uint16，全系统有效组数 G，所有板一致
```

CONFIG_ID 标识包含所有板卡映射和 ON/OFF sequence 的一整套配置。它在 V1 用于配置与启动前核对，不放入故障帧。

格式版本 2 用于区分旧草案中“表 A 存 GROUP_ID”的版本 1，旧映射不能按新索引解释，需由上位机重新生成并下发。该版本号不改变本文 V1 的功能范围。

现有 PC 通信的帧校验继续使用。新映射命令沿用现有 OFFSET + DATA 的分块写入方式；下发后进行完整读回比较，再由上位机提交配置有效。V1 不另加一套整镜像 CRC 协议。

命令功能需要包括：开始配置、映射写入/读回、配置提交、状态查询、统一清故障。具体命令码由现有命令表分配，本文不占用未确认的数值。

### 5.2 配置流程

```text
整机下电，START_SYNC=Low，序列停止，EN=0
    ↓
上位机计算保护组及各板两张表
    ↓
各板进入配置状态：撤销启动许可，config_valid=0
    ↓
写入 ON/OFF sequence、完整 1280-word 映射和元数据，未用项为 0
    ↓
读回比较；检查序列、通道范围、表 B 升序和表 A/B 索引一致性
    ↓
上位机逐板提交；各板置 config_valid=1
    ↓
20 块板全部就绪，CONFIG_ID 一致
    ↓
上位机授权 Board0 启动，START_SYNC 上升沿统一上电
```

配置期间不接受启动，写入失败或中止时保持无效，不自动恢复 READY。

V1 使用单份配置 RAM，不要求双缓冲。配置正确性主要由上位机生成、检查和读回确认；FPGA 至少检查状态、地址范围、GROUP_COUNT 及提交条件。

未使用通道必须始终禁止输出。当前实际引出的 112 路与内部 128 路之间，通过固定有效通道掩码约束；高 16 路尚未引出时，上位机不得将 DUT 配置到这些通道。

## 6. 本地故障与跨板关断

### 6.1 本地故障

```text
故障检测输入给出本板通道
    ↓
立即锁存该通道 inhibit，先关闭故障通道
    ↓
读 CHANNEL_ROW_CODE，检查 row_code 后减一，直接读取表 B 对应行
    ↓
fault_inhibit_mask |= 本板组 EN_MASK
    ↓
将该表行对应的 pending 位置 1
    ↓
故障发送模块依次发送 pending 保护组
```

若有效工作通道故障却查不到合法映射，按配置异常处理：本板全部关闭、锁存异常、禁止重新启动，并供上位机查询。该异常不虚构 GROUP_ID 广播；正常配置验收应确保此路径不出现。

### 6.2 收到远端故障

```text
收到完整合法 KILL_GROUP 帧
    ↓
在本板表 B 有效行内二分查找 GROUP_ID
    ├─ 找到：锁存该组 EN_MASK，然后 ACK
    └─ 未找到：本板无该组电源，正常 ACK
```

“未找到也 ACK”仅适用于本板配置有效的情况；配置无效不能以无本地成员为理由确认处理完成。

收到远端 KILL 只执行和 ACK，不再广播同一事件。重复收到同组 KILL 仍执行幂等关断并 ACK。

### 6.3 最少运行状态

- fault_inhibit_mask[127:0]：已经禁止输出的通道，置位保持到统一清除。
- group_fault[127:0]：按本地组表行号记录已锁定的组。
- pending[127:0]：本地产生、等待广播的组。
- 当前发送事务：GROUP_ID、FAULT_CODE、EVENT_ID、重试计数。
- 最近失败状态：missing_ack_bitmap[19:0]、comm_fault。

同组重复本地告警合并为一个关断请求。记录首发故障通道和原因即可，V1 不实现复杂故障历史队列。

多个新本地通道故障应先锁存在通道位图中，再依次查表，不能因为查表忙丢失短脉冲。远端接收和本地查表通过简单请求仲裁串行处理；只有已接收并执行的请求才能 ACK。

### 6.4 完整例子：从接线、两张表到跨板关断

#### 6.4.1 实际接线和上位机分组

沿用第 2.1 节的 A、B、C 关联关系，把四路电源放到三块板上。另加 DUT D、E，展示不属于故障组的电源保持开启。

| 电源 | 实际控制通道 | 供给哪些 DUT | 上位机算出的 GROUP_ID |
|---|---|---|---|
| P1 | Board0.CH1 | A、B 共用 | 0x0002 |
| P4 | Board0.CH4 | A | 0x0002 |
| P2 | Board1.CH3 | B、C 共用 | 0x0002 |
| P3 | Board2.CH6 | C | 0x0002 |
| P5 | Board0.CH7 | D | 0x0001 |
| P6 | Board1.CH9 | D | 0x0001 |
| P7 | Board2.CH2 | E | 0x0003 |

```text
GROUP 0x0002：DUT A、B、C
    Board0：CH1、CH4
    Board1：CH3
    Board2：CH6

GROUP 0x0001：DUT D
    Board0：CH7
    Board1：CH9

GROUP 0x0003：DUT E
    Board2：CH2
```

这里减少了每个 DUT 的电源路数以便阅读，实际五路或更多路的处理方式相同。其余 17 块板仍在线，但在本例中不含 0x0002 组。

#### 6.4.2 上位机实际下发哪些表

**表 A：通道号作为数组下标，内容为本地表 B 行号加一，不是 GROUP_ID。**

| 板卡 | 表 A 中的有效内容 |
|---|---|
| Board0 | CHANNEL_ROW_CODE[1]=0x0002；[4]=0x0002；[7]=0x0001 |
| Board1 | CHANNEL_ROW_CODE[3]=0x0002；[9]=0x0001 |
| Board2 | CHANNEL_ROW_CODE[2]=0x0002；[6]=0x0001 |

这三块板的其他表 A 项在本例中均写为 0。Board2.CH6 的编码为 1，即本地 row=0；该行实际 GROUP_ID=2，清楚区分了行号编码和全局组号。

**表 B：按 GROUP_ID 严格升序，每行保存组号和本板 EN_MASK。**

下表只写掩码低 16 bit，高 112 bit 全为 0。

| 板卡 | 本地行号 row | GROUP_ID | EN_MASK[15:0] | 掩码置 1 的通道 |
|---|---|---|---|---|
| Board0 | 0 | 0x0001 | 0x0080 | CH7 |
| Board0 | 1 | 0x0002 | 0x0012 | CH1、CH4，即 (1<<1) \| (1<<4) |
| Board1 | 0 | 0x0001 | 0x0200 | CH9 |
| Board1 | 1 | 0x0002 | 0x0008 | CH3 |
| Board2 | 0 | 0x0002 | 0x0040 | CH6 |
| Board2 | 1 | 0x0003 | 0x0004 | CH2 |

三块板的 GROUP_COUNT 都为 2，GLOBAL_GROUP_COUNT 都为 3。升序排列后，组2在 Board0/Board1 位于 row=1，在 Board2 位于 row=0。**同一 GROUP_ID 在各板的 row 可以不同；通信必须传 GROUP_ID，不能传 row 或 row+1。**

例如 Board1 的实际 RAM 内容为：

```text
表 A：
RAM[3]   = 0x0002       // Board1.CH3 指向 row=1
RAM[9]   = 0x0001       // Board1.CH9 指向 row=0
其余 RAM[0..127] = 0

表 B 第 0 行，起点 128 + 0*9 = 128：
RAM[128] = 0x0001       // GROUP_ID
RAM[129] = 0x0200       // EN_MASK[15:0]，只包含 CH9
RAM[130..136] = 0       // 掩码其余 7 个 word

表 B 第 1 行，起点 128 + 1*9 = 137：
RAM[137] = 0x0002       // GROUP_ID
RAM[138] = 0x0008       // EN_MASK[15:0]，只包含 CH3
RAM[139..145] = 0       // 掩码其余 7 个 word
```

写入 Board1 表 B 第 1 行时，PC 映射写命令的 payload 可表示为：

```text
OFFSET：00 89                         // 137，单位为 16 bit word
DATA：  00 02  00 08  [00 00 重复7次]  // GROUP_ID + 8个掩码word
```

这里展示的是映射写命令内部的 OFFSET/DATA，外层 PC 通信帧仍沿用现有协议。两表在配置阶段写好，发生故障时不再临时下发。

#### 6.4.3 Board0.CH1 故障后，本板如何动作

假设正常上电序列已经完成，START_SYNC 保持 High，本例七路电源都处于开启状态，初始 fault_inhibit_mask 为 0。

故障检测模块报告 Board0.CH1 故障。以下接口名仅用于说明拟议模块连接，不代表现有 RTL 已包含这些端口：

```text
故障检测 → 故障控制：local_fault_valid=1，local_fault_channel=1
```

Board0 依次执行：

1. 立即置 fault_inhibit_mask[1]=1，先关闭本地 CH1。
2. 读取表 A 的 RAM[1]，得到 row_code=2；检查 1≤2≤GROUP_COUNT，减一得到 row=1。
3. 直接读取表 B 第 1 行 RAM[137..145]，得到 GROUP_ID=2、EN_MASK=0x0012，不做组号搜索。
4. 将 0x0012 合入 fault_inhibit_mask，本板 CH1、CH4 全部禁止开启。
5. 本地 row=1，因此置 group_fault[1]=1、pending[1]=1。
6. 发送模块选择 pending[1]，直接读取表 B 第 1 行的全局 GROUP_ID=2，准备广播。

本板低 16 bit 输出变化如下，高位均为 0：

```text
正常请求 selected_en     = 0x0092    // CH1、CH4、CH7
先锁存故障通道后 actual_en = 0x0090    // CH4、CH7
整组 inhibit 锁存后：
    fault_inhibit_mask   = 0x0012    // 禁止 CH1、CH4
    actual_en            = 0x0080    // 仅 CH7 继续开启
```

CH7 属于 0x0001 组，不受本次故障影响。本地关断过程中不等待 FAULT_REQ 仲裁，也不等待远端 ACK。

#### 6.4.4 板间实际传什么信号、什么数据

假设此次只有 Board0 有待发送故障，Fault Bus 原本空闲：

| 信号/通道 | 本次动作 |
|---|---|
| START_SYNC | 始终保持 High，本次组故障不触发整机 OFF_SEQUENCE |
| FAULT_REQ | Board0 拉低发起请求阶段，释放形成公共仲裁起点；获胜后再次拉低，保持到帧、ACK 和必要重试结束 |
| FAULT_A/B | Board0 发送 8 Byte 的 KILL_GROUP 故障帧，随后各板在固定时隙返回 ACK 脉冲 |
| 本板 EN 引脚 | 由各板自己的 fault_inhibit_mask 屏蔽，不通过板间线逐路传 EN |
| PC RS485 | 本次实时关断无需 PC 命令；PC 后续可以查询状态 |

假设 FAULT_CODE=0x01、EVENT_ID=0x2A。0x01 仅为本例原因码，不在这里确定正式故障类型编码。

```text
字段：SOF  SOURCE  GROUP_H GROUP_L FAULT EVENT CRC_H CRC_L
字节： A5     00      00      02     01    2A    8F    05
```

CRC 按第 8.1 节算法对 `00 00 02 01 2A` 计算，结果为 0x8F05，高字节先发送。每个字节通过 UART 8N1 发送，UART 字节内按低位先发；这与多字节字段采用大端不冲突。

这帧表达的是“Board0 通知全系统关闭 GROUP 0x0002”。帧里没有 DUT A/B/C 列表、各板 EN_MASK、目标板卡地址或本地 row；所有板卡都监听同一广播。

#### 6.4.5 Board1 收到后，具体查什么

Board1 收到完整 8 Byte，检查 SOF、字段范围和 CRC。通过后向本地故障控制模块提交拟议信号：

```text
remote_kill_valid = 1
remote_group_id   = 16'h0002
```

远端事件已经携带 GROUP_ID，所以 Board1 **不查表 A，也不读取本板 CH1**。SOURCE_ID=0 只表示发送者是 Board0，不代表本板要关 CH0 或 CH1。

对表 B 做二分查找的具体过程：

```text
目标 GROUP_ID = 0x0002

lo=0，hi=2，mid=(0+2)>>1=1
row=1：读取 RAM[137] → 0x0002，与目标相同，一次比较即找到
       读取 RAM[138..145] → 本板 EN_MASK=0x0008
       fault_inhibit_mask |= 0x0008
       group_fault[1] = 1
       本地关断处理完成，可以准备 ACK
```

这是同步 RAM 的多周期操作，先发地址，再等待数据返回，并非同一拍完成整个搜索。初始搜索范围为 `[0, GROUP_COUNT)`，不读取尾部填零行；匹配后才读取该行掩码。

Board1 原来 CH3、CH9 开启，selected_en=0x0208；本次 inhibit=0x0008，因此 actual_en=0x0200，只关闭 CH3，CH9 继续开启。

Board1 不设置用于转发本次远端事件的 pending，不再广播同一 KILL。其 group_fault[1] 对应本地 row=1；该例恰好与 Board0 相同，但不能据此假设各板行号相同。

#### 6.4.6 Board2 和无本地成员的板卡如何处理

Board2 同样在自己的有序表 B 中做二分查找：

```text
lo=0，hi=2 → mid=1：读 RAM[137]，GROUP_ID=3 > 目标2
    更新 hi=1，保留左半区间 [0,1)
lo=0，hi=1 → mid=0：读 RAM[128]，GROUP_ID=2，匹配
    读 RAM[129..136]，得到 EN_MASK=0x0040
    锁存 inhibit 并关闭 CH6，group_fault[0]=1，准备 ACK

selected_en=0x0044 → actual_en=0x0004，CH2 继续开启
```

Board3 等不含组2的板卡，二分查找收敛到空区间后返回未找到；若 GROUP_COUNT=0 则直接返回。目标组号合法且本板配置有效时，确认“本板无需关闭通道”，保持 EN 不变并正常 ACK，不扫描所有行。

#### 6.4.7 ACK、结束和最终状态

Board0 发完故障帧后关闭自己的 RS485 Driver，使 DE=0 并保持接收；等待 turnaround 后进入 ACK 时隙。

- Board1 在 ACK_SLOT[1]、Board2 在 ACK_SLOT[2] 内返回约 5 us 的有效差分脉冲，其他板同样只在自己的时隙响应。
- ACK 脉冲由 Fault Bus 模块控制 DE 和驱动电平产生，不是 UART ACK 字节，也不是拉动 FAULT_REQ。
- Board0 的自身 ACK 位直接置 1；收到其他 19 板 ACK 后，ack_bitmap[19:0]=20'hFFFFF。
- Board0 完成本次发送、清除对应 pending/在途状态、释放 FAULT_REQ。若缺 ACK，则按第 8.3 节重试同一 GROUP_ID 和 EVENT_ID。
- pending 清除只表示通知事务结束，**不会清除 group_fault 或 fault_inhibit_mask**。

三块板的最终低 16 bit 状态为：

| 板卡 | 正常 EN 请求仍为 | 本次故障 inhibit | 实际 EN 输出 | 仍在工作的 DUT 电源 |
|---|---|---|---|---|
| Board0 | 0x0092 | 0x0012 | 0x0080 | DUT D 的 P5 |
| Board1 | 0x0208 | 0x0008 | 0x0200 | DUT D 的 P6 |
| Board2 | 0x0044 | 0x0040 | 0x0004 | DUT E 的 P7 |

因此 A、B、C 的 P1/P2/P3/P4 全部收到关闭 EN；D、E 的电源继续工作。START_SYNC 仍为 High，正常 EN 请求也可以保持原值，但保护组 0x0002 已被持续屏蔽，不会因此重新打开。

这里的“关断完成”指 EN 已关闭并锁存，实际电压下降仍取决于电源和负载，不由 ACK 确认。

本例中两张表的用途可直接记为：

```text
本地发现故障：CHANNEL → 表 A 得 row+1 → 减一 → 直接读表 B → GROUP_ID/EN_MASK
收到远端故障：报文 GROUP_ID → 二分查找有序表 B → 本地 row/EN_MASK
发送 pending：本地 row → 直接读表 B → GROUP_ID → 广播

板间传的是全局 GROUP_ID；真正关闭哪些 EN，由接收板自己的表 B 决定。
```

## 7. EN 输出与序列的配合

最终引脚前统一施加故障屏蔽：

```verilog
actual_en = selected_en
          & valid_channel_mask
          & ~fault_inhibit_mask
          & {128{output_permit}};
```

- selected_en：由明确的正常/调试模式选择，正常模式使用 sequence_en_state。
- output_permit：配置有效且允许输出；复位、配置期间或整板停机时为 0。
- fault_inhibit_mask：对正常序列和调试控制都有效，没有调试绕过入口。

保护组故障时，其他保护组的正常序列可以继续执行。后续序列即使要求故障通道为 1，也被最终屏蔽。

现有 i_emergency_off 会中止序列并清零全板 EN，仅保留给整板紧急停机，不用于单个保护组关断。

START_SYNC 表示整机正常目标状态，不直接作为 sequence/debug 的选择信号。Low 时仍需执行 OFF_SEQUENCE，序列结束后保持最终状态。

V1 对正常操作采用简单限制：上位机必须等待 ON_SEQUENCE 完成后才允许正常下电，等待 OFF_SEQUENCE 完成后才允许下一次上电。需要立即停止时使用故障关断/整板急停路径，不把急停当成普通序列启动命令。

这项限制避免初版立即实现正常 ON/OFF 序列相互抢占；不能仅发一个新的 i_start 脉冲并假设忙碌中的执行器会接受。

## 8. 故障总线：保留基础方案，只改必要项

### 8.1 V1 固定 8 Byte 故障帧

沿用原 UART 8N1、400 kbit/s、固定 ACK 时隙和最多重试 2 次，仅将原 1 Byte DUT_ID 替换为 2 Byte GROUP_ID：

| Byte | 字段 |
|---|---|
| 0 | SOF = 0xA5 |
| 1 | SOURCE_ID，0..19 |
| 2 | GROUP_ID_H |
| 3 | GROUP_ID_L |
| 4 | FAULT_CODE |
| 5 | EVENT_ID |
| 6 | CRC16_H |
| 7 | CRC16_L |

CRC 使用原 CRC-16/MODBUS 算法：Init=0xFFFF，反射多项式 0xA001，RefIn/RefOut=true，XorOut=0。覆盖 Byte 1..5，CRC 高字节先发送。

V1 所有合法帧均表示 KILL_GROUP，不引入 TYPE、在线清除、运行轮次等字段。CRC 错误、SOURCE_ID 越界、GROUP_ID 为 0/0xFFFF 或大于 GLOBAL_GROUP_COUNT 的帧不执行、不 ACK。合法组号但本板无成员时可以 ACK。FAULT_CODE 用于诊断，不改变关断范围；保留类型可按通用故障显示，不能因未识别原因而忽略有效 KILL。

EVENT_ID 保留 8 bit，同一次重试不变；V1 不根据 EVENT_ID 丢弃 KILL，避免回绕去重逻辑。关断本身幂等，重复帧仍需 ACK。

### 8.2 仲裁必须有共同轮起点

原规则“各板发现 pending 后分别等待 BOARD_ID 时隙”不能保证互斥，不应原样照搬到多板实现。两个不同时间发现故障的节点可能恰好在同一时刻竞争。

V1 可继续使用同一根 FAULT_REQ 和固定 BOARD_ID 时隙，通过增加一个短暂的请求阶段建立共同起点：

```text
IDLE
 → 有 pending 的节点拉低 FAULT_REQ，发起请求阶段
 → 所有节点观察到 Low，进入本轮等待状态
 → 请求节点在规定的短脉冲结束后释放 FAULT_REQ
 → 所有节点以共同的 Low→High 作为本轮仲裁起点
 → 等待 REQ_RELEASE_GUARD + BOARD_ID × ARB_SLOT
 → 唯一获胜节点拉低 FAULT_REQ，开始故障帧/ACK/重试
 → 事务结束释放，所有节点回到 IDLE
```

请求脉冲第一版可取 20 us；多个请求节点同时拉低时，都必须在有限脉冲时间后释放，以最后的总线释放上升沿建立轮起点。

只有进入本轮候选集合的节点参与该轮；仲裁起点之后新增的故障保留 pending，等待下一轮。进入请求/仲裁/事务阶段的节点不得再发起新的请求脉冲。请求阶段的 Low 和取得所有权后的 Low 由状态机阶段区分。

每个节点到自身时隙前持续监听 Low；发现其他节点取得所有权后停止竞争。接收同步、线路识别偏差和保护间隔仍需板级验证。

此处是原仲裁方案的必要补充，不在 V1 引入公平调度、动态优先级或多主复杂协议。

### 8.3 ACK 和失败处理

- 保留 Board0..Board19 共 20 个固定 ACK 时隙；V1 要求 20 板均在线。
- 发送方自身位视为完成，其他板在自己的时隙内 ACK。
- ACK 表示 EN 关断命令已落实并锁存，不代表电压已放电至安全阈值。
- 未集齐 ACK 时最多重发 2 次；重试后必须释放总线，不能永久占用。
- 重试耗尽：保存 missing_ack_bitmap，锁存 comm_fault，保持故障 inhibit，撤下本板继续启动的许可；记录并结束当前发送事务，允许其他 pending 故障继续发送。
- 上位机发现 comm_fault 后要求整机停止并检查，不执行自动清故障或重新上电。

V1 **不保证通信链路彻底失效时，远端一定完成关断**。整机通信失效后的独立硬件停机属于后续升级项。

### 8.4 时间说明

8 Byte 帧在 400 kbit/s、8N1 下需要 200 us。

沿用原参数，建立仲裁轮后，Board19 的仲裁等待为 210 us；帧发送 200 us、turnaround 10 us、20 个 ACK 时隙 200 us，合计约 620 us。

采用上述请求阶段时还需增加请求脉冲及输入识别时间。以上均不包含故障检测、查表、已有事务排队和重试，不作为系统最坏 1 ms 保证。

## 9. 故障清除：只做整机统一清除

```text
上位机要求正常整机下电
    ↓
START_SYNC=Low；所有序列停止；实际 EN=0
    ↓
确认故障源解除、通信恢复；故障总线事务结束
    ↓
正常和调试 EN 请求均清零
    ↓
逐板清除 inhibit、group_fault、pending 和通信异常状态
    ↓
确认全部 20 板完成清除、配置有效、CONFIG_ID 一致
    ↓
重新授权统一上电
```

清除期间关闭启动许可。清除和新故障同拍时，新故障置位优先。仍存在故障时不得报告可启动。

清除事务必须在故障总线空闲、旧 pending 已排空或按停机流程撤销后进行，避免旧 KILL 在清除后再次到达。V1 不提供带电单组清除命令。

复位后本板输出关闭、配置无效；即使 START_SYNC 已为 High，也不得自动上电，必须重新完成配置和下一次有效启动流程。

## 10. 对现有设计的具体修改清单

| 对象 | V1 拟修改内容 |
|---|---|
| 上位机配置生成 | 全局连续编号；表 B 升序后生成表 A 的 row+1；生成组数/版本元数据，完整下发及读回确认 |
| en_control_application 或独立配置模块 | 增加映射写入/读回、配置提交和清故障接口；现有时序写入也受停机配置状态约束 |
| 新映射 RAM/查表模块 | 保存本板两表；本地通道经表 A 直接索引、按 GROUP_ID 二分查找、按 row 直接读取 |
| 新故障控制模块 | 通道故障锁存、组掩码关断、group_fault 和 pending 管理 |
| Fault Bus 模块 | GROUP_ID 扩为 16 bit；固定帧改为 8 Byte；补共同仲裁起点；接入 ACK 和 pending |
| 顶层 EN 输出 | 明确正常/调试模式，最终加入有效通道掩码、inhibit 和输出许可 |
| en_sequence_controller | 继续执行现有绝对 EN 序列；不增加 DUT/保护组解析；整板急停接口保持原用途 |

最小模块关系：

```text
PC：DUT接线 → 保护组计算 → 本板sequence + 两张映射表
                                      ↓
本地故障通道 → 查表 → fault_inhibit_mask ← 远端KILL_GROUP
                         ↓
正常/调试EN ────────── 最终屏蔽 ────────── 实际EN

本地新故障 → pending → Fault Bus发送/ACK/重试
```

## 11. V1 最小验收项目

1. 一个组跨多板：任意成员通道故障后，所有成员 EN 关断，其他组不变。
2. DUT 通过共享电源间接关联：上位机生成同一组，一次 KILL 覆盖整个关联范围。
3. 故障发生在上电序列中：故障组后续步骤不能重新打开，其他组继续执行。
4. 本板无该组：配置有效时正常 ACK；配置无效时不 ACK。
5. 同组多次故障、重复帧和重试：不重新上电，不形成广播循环。
6. 两块板在不同时间产生故障：仲裁不发生双发送；未完成组保留 pending。
7. CRC 错误、缺 ACK、重试耗尽：不误报全部完成，总线最终释放，异常保留。
8. 清故障时 EN 请求为 0，清除本身不会导致重新上电。
9. 配置中断、无效映射和 FPGA 复位：禁止启动；START_SYNC 已为 High 时不自动上电。
10. 上位机配置通道范围与实际 112/128 路硬件一致，未使用通道无法开启。
11. 空表、单行、128 行、组号空洞及不存在的目标：二分查找正确终止；首尾行均可命中，128 行最多比较 8 次。
12. row_code=0、128、越过 GROUP_COUNT；表 B 非升序、重复组号或表 A 指错行：配置/运行范围检查不误读；排序后表 A 必须重新生成。

以上为后续实现验收要求，本文未执行 RTL 仿真、综合或硬件验证。

## 12. 后续升级考虑

以下能力不作为 V1 的实施前提；其缺失对应的能力边界需保留，不能把初版当成已具备完整失效保护的系统。

### 12.1 通信与节点失效保护

- 独立于 Fault Bus 的整机紧急停机硬件路径。
- 板卡心跳、复位/掉电/掉线检测，以及失联板卡涉及保护组的自动关断。
- FAULT_REQ 卡 Low、收发器 DE 卡住、链路断线的自动检测及升级处理。
- 更严格的 ACK 波形判定，避免卡电平或噪声被误判为有效 ACK。

### 12.2 多故障性能

- 仲裁公平性、有界等待，防止固定优先级下低优先级节点长期等待。
- 单帧携带多个 GROUP_ID 或组位图，降低大量故障时的排队时间。
- 明确最坏检测延迟、跨板关断延迟与全部 ACK 延迟，并据此调整总线和硬件。
- 高速故障检测链路与慢速状态采样的分层处理。

### 12.3 配置与协议增强

- 将 CONFIG_ID、运行轮次或启动代号放入故障帧，隔离旧帧和错误版本。
- 配置镜像 CRC、双缓冲及原子切换；需要时再支持在线配置。
- 动态板卡集合、组成员板卡掩码以及更细的 ACK 失败处理。
- 更完整的事件编号、诊断信息、历史日志和根因关联。

### 12.4 下电和恢复能力

- 根据器件要求增加专用故障下电顺序，区别于当前立即屏蔽。
- 根据电压采样确认实际放电完成，检查残余供电、反向供电等路径。
- 正常 ON/OFF 序列抢占和执行中目标状态切换。
- 带电单组故障清除、跨板协调恢复、单组重新上电。

### 12.5 更小的故障隔离范围

- 优化公共电源接线，减少保护组包含的 DUT 数量。
- 增加 DUT 分支独立开关，实现更细粒度断电。
- 如果硬件能直接提供 DUT 级故障信息，再扩展 DUT 级诊断；共享电源告警本身只定位到电源/保护组，不应直接认定某一个 DUT 是根因。
