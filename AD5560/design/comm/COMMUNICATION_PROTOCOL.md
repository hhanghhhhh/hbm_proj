# FPGA UDP 通信协议规范

## 1. 帧格式

每个 UDP Payload 承载一帧完整的请求或响应，不再使用串口协议中的 SOF、ADDR。

| 字段 | 长度 | 说明 |
|---|---:|---|
| CMD | 1 Byte | 业务命令 |
| SEQ | 1 Byte | 请求序号 |
| LENGTH | 2 Byte | PAYLOAD 字节数 |
| PAYLOAD | N Byte | 请求参数或响应内容 |
| CRC | 2 Byte | CRC-16/MODBUS |

```text
CMD | SEQ | LENGTH | PAYLOAD | CRC_H | CRC_L
```

- 所有多字节字段统一采用**大端**（高字节在前），包括 `LENGTH` 和 `CRC`。
- `LENGTH` 范围为 0～1024 Byte，UDP Payload 总长度必须等于 `6 + LENGTH`。
- 单包业务数据最多 1024 Byte；更大数据由业务命令分包，不依赖 IP 分片。
- CRC 覆盖 `CMD` 至 `PAYLOAD`，不包含 CRC 自身；采用 CRC-16/MODBUS（初值 `0xFFFF`，反射多项式 `0xA001`，结果不异或）。

## 2. 请求与响应

采用**单主机、严格一问一答**：主机收到当前请求的完整响应后，才发送新请求；不支持并发事务。

- 响应的 `CMD`、`SEQ` 与请求一致。
- 响应 `PAYLOAD = STATUS(1 Byte) + DATA(N Byte)`，因此响应 `LENGTH >= 1`。
- `STATUS = 0` 表示成功；非零表示业务错误，具体状态码由命令定义。
- 请求可无参数（`LENGTH = 0`）；`SEQ` 为 8 bit，新请求递增，允许回绕。

## 3. 校验与错误处理

- UDP 长度不匹配、`LENGTH` 越界、CRC 错误或报文不完整：**丢弃，不响应，不执行业务**。
- 帧合法但 CMD 未定义、参数不合法或状态不允许执行：返回非零 `STATUS`。
- 完整报文通过检查后，才允许执行配置更新及其他关键控制命令。

## 4. 超时重发与去重

- 主机等待响应超时后可重发，**重发时 SEQ 和请求内容必须保持不变**；超时时间和重试次数由主机配置。
- FPGA 缓存**最近一条已完成请求及其响应**；收到相同 SEQ、相同请求内容的重发时，不再执行业务，直接重发缓存响应。
- 正在执行的请求收到重复报文时不重复执行；同一 SEQ 携带不同请求内容视为协议错误。
- 仅保障当前一问一答场景的最近请求去重；复位后缓存失效，不保证跨复位的严格一次执行。关键动作应另有业务状态确认机制。

## 5. 实现原则

- RX 接收完整 UDP 报文并校验通过后，再向业务模块提交命令。
- TX 准备好完整响应和长度后，再发起 UDP 发送请求。
- 请求和响应均流式计算 CRC；不支持多请求流水及响应排队。
