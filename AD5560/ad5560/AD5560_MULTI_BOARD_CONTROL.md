# AD5560 多板供电控制方案

## 整机与通信网络

整机对上位机呈现 220 路电源。10 块 AD5560 子板各提供 22 路输出，每板 11 条 SPI BUS、每条 BUS 挂 2 颗 AD5560。每个 DUT 的供电组可以从 220 路中选取通道，优先同板，也可以跨板。时序约束针对各路**实际开始 Ramp 输出的时刻**，允许 ms 级偏差，同一 BUS 的两颗器件可以依次启动。组内一路故障，整组下电并隔离输出，同板其他 DUT 继续运行。

板间通过 Aurora 通信。通信层负责路由和仲裁，既能按板卡号寻址，也能将业务载荷（payload）直接送到目的板内指定的模块接口。每块板可在例化通信层时配置 **1～16 个模块接口**。上位机可以直达总控或任意子板的业务模块，板卡之间也可以用同样的方式互发报文。目的模块的标识与 payload 中的功能码各有用途，前者决定报文交给谁，后者由接收模块解释。

**总控是整机调度的逻辑角色**，可部署在独立控制板，也可部署在一块 AD5560 子板的 FPGA 中。共板时，整机调度命令和本板业务仍可分别寻址，具体模块地址在板卡接口表中分配。下文的三个子板接口仅统计本板电源、继电器和采样业务。

### 单接口与三接口接法

| 接法 | 以发送 `RELAY_CONNECT(mask22)` 为例 | 命令处理与回包 |
|---|---|---|
| 1 个统一接口 | 通信层将 payload 送到子板统一入口，本地分发器识别功能码并交给继电器模块 | 分发器译码各类命令，汇集执行结果并通过统一接口回包。继电器等待稳定期间，入口仍应能接收到期启动和故障请求 |
| 3 个模块接口（推荐） | 发送方选中目的板的继电器接口，通信层直接投递 payload | 电源控制、继电器、采样与测量各接一个通信接口，各自译码本模块的功能码并通过本接口回包。子板省去全板统一分发与回包选择逻辑 |

三接口按业务边界划分。AD5560 电源控制接口除了 Config，还接 Ramp 启动、寄存器读回、电源状态和故障下电。同一接口收到 `CFG_LOAD` 与 `TRIP_MASK` 后分别交给 Config 和本地故障状态机，故障请求应能及时受理。三个接口共用板间链路，长采样回包与控制报文竞争时的等待取决于通信层的仲裁和缓存。

## 功能放在哪里

| 谁执行 | 持有的数据 | 负责的动作 |
|---|---|---|
| 上位机（Python） | 220 路通道映射、DUT 分组、多套电压方案、完整寄存器目标值、上电计划 | 把电压、斜率、档位、限流等换算成有序的寄存器地址和完整数据，按板拆包，准备通道，等待结果，处理调试、测量换算、显示和 CSV 记录 |
| 总控逻辑 | 已装载的故障分组表、定时事件表、各活动组的运行状态 | 按硬件计数器发送到期的 Ramp 命令，收到通道故障后取消该组待发事件并协调跨板下电，汇总各板结果 |
| AD5560 子板 | 本次配置记录、各通道准备状态与 0 V 码、22 位故障屏蔽、IO 映射和输出字 | 执行本板 SPI 写入和诊断读回、固定继电器时序、采样、告警定位及故障隔离，回报本地通道结果 |

**能由 Python 完成且不影响动作时刻的流程，优先留在 Python。** 例如计算斜率、生成寄存器表、并行准备多块板、等待全部就绪，都可以在启动前完成。跨板的 0、2、5 ms 启动点放在总控，从一笔 I²C 写成功起算的继电器稳定等待放在子板。必须在上位机离线时仍能完成的整组故障下电，由总控和子板接力执行。

**按数据量和允许时延决定是否预载。** 单次调参、读寄存器和自检开关可以按需直发。若到点后再传整张配置表、完成 SPI 写入或等待继电器稳定会超过时间预算，就提前下发并完成准备，到点只发短命令。子板的 `CFG_LOAD` 只装载和校验记录，`CFG_EXEC` 才写器件。总控和上位机应能区分已配置到 0 V、已接通继电器以及已具备启动条件。

首版由 Python 保存多套方案，把本次要用的参数直接送到各子板，总控预载分组表和启动事件表。如果后续要求上位机离线时仍可按方案号切换电压或重做准备，可把 Python 已编好的“目的板卡号、目的模块接口、子板命令、载荷”按方案缓存在总控。总控只需按准备顺序发出同一套命令并等待执行结果，寄存器换算和 IO 映射仍各由一处维护。

## 总控调度表与命令接口

上位机维护“全局通道 → 板卡号、本地通道”的映射。用户按 220 路编辑，Python 在下载前编成板级掩码。`mask220` 的一位对应整机一路，`mask22` 的一位对应目的板的一路。

| 下载到总控的数据 | 建议内容 | 使用方式 |
|---|---|---|
| 故障分组表 | `组号 → [(板卡号, member_mask22), …]` | 总控可从“源板卡号、本地故障通道”反查组号，再查到全部参与板及成员。一个物理通道同时只归一个活动供电组 |
| 定时事件表 | `计划号、组号 → [(相对 T0 的到期时间, 目的板卡号, ramp_mask22), …]` | Python 将用户的 `(mask220, delay_ms)` 拆板并累计时间。`delay_ms` 表示从本批发出到下一批的间隔，间隔 2、3 ms 对应到期点 0、2、5 ms。总控保留事件的组归属供故障取消使用 |

下表按推荐的三接口接法列出命令归属。模块名称和命令名用于说明业务语义，具体接口号、帧头和功能码由协议设计确定。

| 目的地 | 接口草案 | 典型发起方及结果 |
|---|---|---|
| 总控 | `LOAD_GROUP`、`LOAD_PLAN`、`START_PLAN`、`GET_RUN_STATUS` | 上位机装两张表、启动计划、查询当前阶段、各板结果及故障原因 |
| 总控 | `STOP_PLAN`、`TRIP_GROUP`、`REARM_GROUP` | 正常下电前停止该组待发启动事件，紧急下电时取消事件并立即发起整组隔离，故障处理完成后显式恢复启动资格 |
| 子板 · AD5560 电源控制 | `CFG_LOAD`、`CFG_EXEC`、`REG_READ` | 上位机直接配置和调试，可执行单条或批量写。分别回报数据接收／校验、SPI 执行和读回结果 |
| 子板 · 继电器 | `RELAY_CONNECT(mask22)`、`RELAY_ISOLATE(mask22)`、`RELAY_SET(本地资源, 开关)` | 上位机调用完整接入／隔离流程，也可单控通道或自检继电器。返回完成与失败的通道或资源 |
| 子板 · AD5560 电源控制 | `RAMP_START(mask22)`、`TRIP_MASK(mask22)` | 总控在到期或故障时发送，上位机单板调试复用相同命令。启动时检查就绪与屏蔽状态。故障请求直接交给本地故障状态机 |
| 子板 · AD5560 电源控制 | `GET_STATUS`、`READ_ALARM`、`CLEAR_ALARM` | 上位机查询通道准备、故障屏蔽及器件告警。本接口向总控主动上报带源板卡号、本地通道号和原因的 `FAULT_EVENT` |
| 子板 · 采样与测量 | `READ_MEAS`、`READ_TEMP` | 上位机取 ADC 样本、有效标志和传感器温度，测量结果由本接口返回 |

总控和 Python 向同一子板模块发送同一命令时，使用相同的载荷和执行语义。测量轮询、原始寄存器读写和继电器单控均可直接到目的板。正在由总控调度的组如需停止，应先通知总控取消待发事件。手动改变关键寄存器或输出接线后，子板更新对应通道的准备状态。

## 示例：十路电源跨两板上电

1. **建立故障联动。** Python 先向总控装载 DUT7 的故障分组和定时计划，使分组在接入输出前生效。
2. **配置与接入。** Python 直接向 A、B 两板的电源控制接口下发本批完整寄存器配置，准备 0 V 起点、限流、Ramp 终点、步长和分频。`0x41` 由后续启动命令写入。SPI 执行完成并经过规定的稳定等待后，Python 向两板的继电器接口发 `RELAY_CONNECT(mask22)`。子板执行固定接入流程，返回就绪与失败掩码。
3. **启动。** Python 收齐本次十路的 `READY` 后向总控发一次 `START_PLAN`。若有通道准备失败，先处理该组已接入的通道，再重新准备。总控接受启动时建立该组的 `T0`，从此由硬件计时。

| 总控发令时刻 | A 板 `RAMP_START` 选中通道 | B 板 `RAMP_START` 选中通道 | 合计 |
|---|---|---|---:|
| `T0` | CH0、CH2 | CH0 | 3 路 |
| `T0 + 2 ms` | CH4 | CH2 | 2 路 |
| `T0 + 5 ms` | CH6、CH8 | CH4、CH6、CH8 | 5 路 |

到同一时刻，总控向各目的板的电源控制接口发送 `RAMP_START(mask22)`。子板将掩码展开，对仍就绪且未被屏蔽的通道写 `0x41 = 0xFFFF`，复用 Config 的写入通路。不同 BUS 可并行，同一 BUS 内依次写入。前批回执用于监测结果，后批按相对 `T0` 的到期时刻发送。各子板无需共同的绝对时钟。SPI 完成、FIN 数字回读匹配和 DUT 实测电压达标分别报告。[AD5560 Ramp 寄存器定义](https://www.analog.com/media/en/technical-documentation/data-sheets/ad5560.pdf)

## 子板继电器与下电

普通通道沿用第一版已调好的接入顺序。在 0 V 下闭合 OUT_EN，等 10 ms 后闭合 EXTSense，同时保持 LocalSense。再等 10 ms 后断开 LocalSense，最后等 10 ms 并回报就绪。隔离顺序为闭合 LocalSense、断开 EXTSense、断开 OUT_EN，中间按已调好的时间等待。由子板固定状态机执行，每步的等待从涉及的 IO 扩展器写成功后起算。

`mask22` 选择本地通道，每一步再将“通道、信号名”映射为具体 I²C 总线、TCA9535 地址和输出位。同一扩展器上的多个目标位合并写入，保留其他通道的位。固定序列、自检单控和故障隔离共用同一份输出字。自检继电器按实际的板级或 BUS 级资源编号寻址。I²C 成功回执表示输出字已写入，实际触点状态需要相应反馈确认。

正常下电时，Python 先请求总控停止该组待发的启动事件，确认后按方案控制各子板归零。采用 Ramp 下电时，检查约定的终点后执行 `RELAY_ISOLATE`。故障下电要在 Python 离线时仍可完成，所需 0 V 码和隔离流程应在通道接入前对子板可用。

## 故障联动与恢复

1. 子板定位故障通道，先锁存本通道的屏蔽，再向总控主动上报。告警查询和下电按 ms 级响应设计。
2. 总控从分组表反查 DUT，取消该组尚未发出的启动位，向各参与板发送 `TRIP_MASK(member_mask22)`。即使与其他组共用同一个到期时刻，也保留其他组的启动位。关断范围覆盖整组，包括继电器已接通但尚未开始 Ramp 的通道。
3. 每块参与板的电源控制接口接收一条 `TRIP_MASK`，本地故障状态机将新掩码并入故障屏蔽，并把屏蔽状态提供给 SPI 和继电器执行逻辑。在 SPI 实际提交和普通继电器合闸前检查受影响通道，包括先前排队的动作，已经提交的事务由驱动收尾。故障下电可在普通 Config 等待 `DELAY` 时取得 SPI／I²C 执行机会。
4. **紧急下电不走 Ramp。** 子板中断正在进行的 Ramp，直写本通道的 0 V 码，再由故障状态机通过板内信号请求继电器模块隔离输出。继电器模块优先处理该请求，按已调好的顺序恢复 LocalSense、断开 EXTSense、断开 OUT_EN，并将结果回送故障状态机。屏蔽保持期间仍允许归零与隔离动作。某一步回读或写入失败时记录原因，继续尝试其余隔离动作，并上报未确认通道。[已有紧急下电要求](user.md)
5. 总控汇总各板的逐通道结果。查告警、清器件锁存和重新使能分别处理，待故障处理完成、旧待发动作已清理，再由总控显式恢复该组启动资格。通信重连时先查询板上状态及配置有效性。

## RTL 影响与联调

- **总控**实现故障分组查找、按组管理待发事件、硬件计时及故障分发。板卡与模块寻址、路由和仲裁复用通信层。
- **子板 Config** 保留并行 `WRITE` 和局部 `DELAY`，`DELAY 0` 可作 SPI 排空屏障。现有 3 位 BUS 编码、8 路队列、就绪向量、仲裁和排空判断需适配 11 条 BUS，并在提交处检查 22 位故障掩码。新版取消旧 `power_sequence_engine` 及正常序列对全局 `abort` 的依赖。[并行 Config RTL](../rtl/config_manager_parallel.v)
- **时序验证**沿总控发令、通信路由／排队、子板 SPI 写入、DUT 实际 Ramp 边沿测量。第一版 SPI 为 1 MHz，单笔 24 位写仅移位约 24 µs，同一 BUS 两颗依次写约 48 µs，另有驱动间隔和等待。联调要覆盖普通配置／测量与到期启动、故障请求同时出现的情况，检查启动偏差和全组封锁时间。
- **待定项**包括 Aurora 核及线速、最终 SPI 频率、可接受的跨板 Ramp 起点最大偏差、告警至整组封锁的最长时间，以及链路中断时已供电通道的处理方式。
